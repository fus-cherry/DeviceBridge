# DeviceBridge 下一批优化建议

基于 0.1.5 Build 123 对应代码的云端源码审查，不是截图评审或真实设备验收。没有访问用户本地，也没有推送或发布本批修改。

## 建议优先级

### 第一优先：基本流程更容易完成

1. 文件夹内搜索和排序：当前 FileTransferView 只有文件夹列表，找大量文件需要滚动。先提供本地名称筛选、自然排序、大文件优先、匹配数量和无结果提示。只处理已加载条目，不扫描设备或读取文件内容。
2. 首次连接引导与能力状态：WorkspaceView 默认进入剪贴板，而鸿蒙主要支持文件和媒体。建议按设备平台选择首个可用模块，并明确区分“未检查、需要授权、缺少工具、不支持”，提供对应恢复操作。连接就绪不应被理解为所有能力就绪。
3. 传输进度与结果：当前传输主要展示旋转指示和最终文本。大视频应显示实际字节进度、当前文件、速度、剩余时间（仅有有效采样时）、可取消状态和“在访达显示”。不要伪造进度或在断连后自动重复安装。

### 第二优先：界面减负

4. 媒体页短说明加可展开细节：PhoneImagesView 的鸿蒙说明包含多段较长限制文本，工具栏和内容之间信息密集。首屏保留“按需导出、可能消耗流量/空间”，其余限制放入“使用说明”，实际导出前仍保留必要风险提示。
5. 文件页分区：将范围/目录浏览、发送与接收、HAP 安装分成清晰区域。HAP 安装和 APK 复制的差异不能隐藏。路径支持复制，长名称提供完整 tooltip。
6. 媒体网格与预览：当前固定 360px 列表和240px预览，且嵌在外层 ScrollView。建议后续在 macOS 实际窗口中验证小窗口、中文长文本、缩放和键盘焦点，再选择分栏预览布局，避免仅凭源码大改。

### 第三优先：开发者效率

7. 失败诊断导出：将当前设备能力、工具版本、脱敏错误和操作结果导出为一份诊断报告。不要包含设备媒体、证书、秘密或完整个人路径；先预览后导出。
8. 显式传输队列：用户可选多个文件、查看队列、取消单项、重试明确失败项。保留设备会话绑定，不跨设备自动重试。大文件断点续传需远端文件身份和完整性协议，不能只做 UI。
9. 目标设备验收矩阵：鸿蒙版本/mediatool、用户文档可见性、拒绝权限、拔线、锁屏、云端原件、特殊文件名、大视频。现有 CI 通过不能代替这些。

## 本批已实施的小改动

在独立云端分支 cloud/usability-next-batch 实现文件夹本地筛选与排序。保持文件夹优先、未知大小排后、自然名称排序；更换设备/范围或进入子目录时清理筛选。增加中文文本与可访问性标识。筛选不会改变原始条目、路径、已选择文件或触发远端操作。

## 暂不建议优先做

- 鸿蒙 root、隐藏相册、绕过权限。
- 把 APK 复制包装成原生安装。
- 为了视觉换肤重写所有模块，或在未做真机验收前继续堆新平台能力。
- 自动清理用户缓存、自动安装/更新或自动上传诊断。

证据位置：apps/macos/DeviceBridgeApp/Views/{WorkspaceView,FileTransferView,PhoneImagesView}.swift；README.md；docs/development.md。这些建议以当前代码为依据，不代表用户已经同意其中每一项。

## 本批验证结果

- 官方 Swift 6.2 云端隔离回归：129 项通过（含新增 5 项文件列表测试）。
- 15 项鸿蒙界面契约 Python 检查通过。
- FileTransferView Swift 语法检查与 git diff --check 通过。
- 当前未运行本批 macOS App 完整构建、视觉/键盘交互验收或设备测试；上批 Build 123 的通过结果不能替代本批验证。
- 独立只读复查未发现阻断问题。后续 UI 验收应覆盖：选中文件后筛选把它隐藏时，路径输入框仍显示原选择且接收按钮可继续操作该路径；可进一步增加显式“当前选择”提示，避免将无匹配误解为无选择。
