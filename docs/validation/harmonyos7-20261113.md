# HarmonyOS 7 限定真机验证记录（2026-11-13）

本记录区分已交付 Build 138 的真实 UI、独立 HDC 命令、候选源码测试。真机测试由获用户授权的独立测试环境执行，云端开发未访问用户本机。未记录设备标识、私人剪贴板、文件正文或媒体缩略图。

## 环境与已证实结果

- HarmonyOS 7，HDC 客户端 `3.2.0f`，`testhelper 1.0.1`。不能泛化到所有 HarmonyOS NEXT、HDC 或 testhelper 版本。
- Build 138 能发现、选择授权设备；目标限定的 `echo devicebridge-ready` 返回精确标记。
- Build 138 图片列表加载 12 项、视频列表加载 2 项，各 1 页。仅验证元数据，不读取/导出原件，不宣称云端原件下载通过。
- 原生 HDC 在独占的 `/data/local/tmp` 测试目录完成 81 字节含中文/Emoji 标记的发送、接收与双端 SHA-256 一致性验证。这是 CLI 调试目录验证，不是新版应用完整传输验收，也不是手机文件管理器可见性证明。
- `testhelper get-pastedata` 在用户给定无害标记上读取准确；写入合成 Unicode 标记后逐字读取匹配，再恢复原测试标记并复核。后续用户改变剪贴板后不再假定仍是原标记。
- Base64 解码加末尾 sentinel 的固定 50 字节无正文探测逐字一致，涵盖引号、命令字符、反斜杠及末尾 LF/CRLF。此探测不调用 testhelper，不读取/写入剪贴板或文件。

## 公共文档写入的系统限制

`/storage/media/100/local/files/Docs` 与其 `Documents` 子目录的存在、读写/执行测试、非符号链接以及 `readlink -f` 均通过；生产 parent 的换行 sentinel 与新 UUID destination 检查也通过。

但在 `Docs/Documents` 创建本次测试独占 UUID 的普通目录和隐藏目录均返回 `Permission denied`，未创建目录。HDC 主机退出码仍为 0，错误位于 stdout、stderr 为空。

因此不能仅凭 `test -w` 或主机退出码声称公共文档可写，也不能把最初未列出子目录的采集结果当作目录不存在。候选代码保留原根目录、规范路径、sentinel、权限与防覆盖保护，识别明确 mkdir 拒绝并提示“未发送”；其他未确认的 setup 不猜测原因。不会改权限、自动换目录、删除既存目标或绕过设备策略。

`/data/local/tmp` 仍仅是调试临时范围，不能冒充手机 Files 可见位置。公共可见交付需要受系统授权的导入/下载路径；浏览器与反向端口方案仅研究中，本版未创建下载服务或端口映射。

## 候选修复与待验收项

- 新 HDC 剪贴板通道仅显式读写才检查能力；选择设备不会读取。读最多 1 MiB UTF-8 完整文本，写客户端保守上限 2 KiB，不能容纳时拒绝而非截断。完整协议仅移除一个末尾 LF，不 trim 用户文字；写入只认可精确成功回执，状态不明不自动重试/回滚。
- 文件选择、保存与确认改为异步原生 sheet，补取消、重开、重复点击、最终确认及切换设备回归。先前 AX 超时不能证明应用死锁；此次公共文档失败已有系统 mkdir 拒绝的独立证据。
- 以上新增通道与文件 UI 尚须最新 macOS CI 和新版应用真机回归，CLI 成功不能替代新 App 验收。
- 设备存在 `snapshot_display`、`/proc/meminfo` 与 `hidumper` 相关能力，不等于当前 App 已适配截图/内存。后续范围须独立实现和测试。`.png` 请求可能主机退出 0 仍报告错误，不能以退出码推断截图成功。
- HAP 实际安装/更新、媒体原件导出、其他系统版本、多用户公共文档可见性仍未通过本次验收。
